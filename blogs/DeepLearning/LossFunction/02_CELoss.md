## 1. 什么是 CELoss

**交叉熵损失（Cross-Entropy Loss）** 适合分类问题，什么是分类问题呢？分类问题的特点是：

- 输出是**概率分布**（比如：猫90%，狗10%）
- 真实标签是 **one-hot 编码**（比如：[1, 0]表示猫）
- 我们需要衡量的是**两个概率分布之间的差异**

`如何衡量"模型预测的概率分布"和"真实标签的概率分布"之间的差距？` 这就是交叉熵要解决的问题！数学公式写做：

$$
\text{CrossEntropy}(y,\hat{y})=-\sum^{C}_{i=1}y_{i}\log{(\hat{y}_{i})}
$$

- $C$：表示类别的数量
- $y=[y_1,y_2,...,y_C]$：真实标签（one-hot编码）**向量**
- $\hat{y}=[\hat{y}_1,\hat{y}_2,...,\hat{y}_C]$：模型预测的概率分布 **向量**
- $log$：表示自然对数，以 e 为底

这个过程也很好理解，还是三步走：

1. ==$\log{\hat{y}_i}$==：对模型预测的概率 **取对数**。诶，这里要注意，概率都是 [0, 1] 区间，所以结果必然 小于等于 0，比如 $log(0.7)\approx{-0.357}$。

2. ==$-\log{\hat{y}_i}$==：把刚才的对数结果 **加负号**。−0.357 变成 0.357，这样损失值就变成正数了。

3. ==$\sum y_{i}\cdot ...$==：最后一步 **加权求和**。用真实标签 $y_{i}$ 作为权重，把所有类别的损失加起来。因为真实标签是 one-hot 编码（只有一个 1，其他都是 0），所以实际上只有真实类别的那一项有贡献。

## 2. 设计哲学：负对数

你可能会问："为什么要用对数？为什么要加负号？"。这就涉及到了交叉熵最精妙的两个设计哲学：

### 2.1 惩罚预测不准

这是交叉熵的灵魂所在。对数函数会对低概率预测进行 **"惩罚性放大"**。请看这个对比：

| 预测概率         | $-\log(\text{概率})$ | 后果                         |
| :--------------- | :------------------- | :--------------------------- |
| **很准 (0.9)**   | 0.105                | 惩罚很轻，模型很开心。       |
| **一般 (0.5)**   | 0.693                | 惩罚中等，模型需要改进。     |
| **很离谱 (0.1)** | 2.303                | **惩罚爆炸！模型痛不欲生！** |

这意味着交叉熵告诉模型：**"你可以不太确定（预测 0.5），我还能接受；但如果你把正确答案的概率预测得特别低（比如 0.1），我会让你付出惨痛代价"**。逼着模型赶紧提高对正确类别的置信度。

### 2.2 符合信息论直觉

对数函数有一个**神奇的性质**：==把概率的乘法变成加法==。假设你连续预测 3 个样本，每个样本预测"猫"的概率都是 0.7：

- **不用对数**：总概率 = $0.7×0.7×0.7=0.343$
- **用对数**：总"信息量" = $\log(0.7)+\log(0.7)+\log(0.7)=3×0.357=1.071$

**为什么要这样做？** 因为概率相乘会变得非常小（0.343 已经很小了，如果是 10 个样本，概率会变成 $0.7^{10}≈0.028$），数值计算会不稳定。

而对数把乘法变成了加法，数值更稳定，也更符合我们对"累积误差"的直觉：每个样本的损失可以简单相加。

## 3. 交叉熵损失的三种分类

### 3.1 二元交叉熵损失

对于**二分类问题**（比如：猫 vs 非猫），交叉熵简化为**二元交叉熵（Binary Cross-Entropy）**：

$$
\text{BCE}=-[y\log{(\hat{y})}+(1-y)\log{(1-\hat{y})}]
$$

- $y\in{\{0,1\}}$：真实标签（1 表示正类，0 表示负类）
- $\hat{y}\in{[0,1]}$：模型预测为正类的概率（**经过 Sigmoid 激活**）

举个例子，真实标签的猫，y=1，模型概率预测的是 0.8，那么计算的结果就是：

$$
\text{BCE}=−[1×\log(0.8)+(1−1)×\log(1−0.8)]=−\log(0.8)≈0.223
$$

可以看到它的 **交叉熵损失** 的值还是比较小的，说明 0.8 的预测概率，准确度还不错。

### 3.2 分类交叉熵损失

**分类交叉熵（Categorical Cross-Entropy）** 就是开篇的公式。用于 **多分类问题**（比如：猫、狗、鸟），标签的格式为：

- 真实标签 $y$ 是 **one-hot 向量**（比如：[1, 0, 0] 表示猫）
- 模型输出 $\hat{y}$ 是概率分布向量（**经过 Softmax 激活**），和为 1

为了强化记忆，这里举一个具体例子：假设真实标签中的猫为 [1, 0, 0]，而模型预测的（猫、狗、鸟）概率为 [0.7, 0.2, 0.1]，那么最终**损失**的计算结果为：

$$
\text{CE}=−[1×\log(0.7)+0×\log(0.2)+0×\log(0.1)]=−\log(0.7)≈0.357
$$

### 3.3 稀疏分类交叉熵损失

**稀疏分类交叉熵（Sparse Categorical Cross-Entropy）** 也是用于 **多分类问题**，区别在于，CE 是 one-hot 向量，而 SparseCE 是 整数索引：

- 真实标签 $y$ 是 **整数索引**（比如：0 表示猫，1 表示狗，2 表示鸟）
- 模型输出 $\hat{y}$ 是概率分布向量（**经过 Softmax 激活**）

**公式写做**：==$\text{SparseCE}=-\log{\hat{y}_{y}}$==

还是举一个例子，真实标签中，猫的索引 y = 0，模型预测的（猫、狗、鸟）概率还是 [0.7, 0.2, 0.1]，最终**损失**的计算结果为：

$$
\text{SparseCE}=−\log(\hat{y}_{0})=−\log(0.7)≈0.357
$$

诶？这个计算结果，和分类交叉熵算出来的不是一样的吗？到底哪里改变了？我们先来做一个假设，**假设我们有 1000 个类别，只有索引 0 和 2 的地方为真，其余都为假**。

- 如果用 CE 来表示，它是 one-hot 编码，1000 个值必须都要写出来：[1, 0, 1, 0, ..., 0]。可以发现，内存浪费严重！
- 如果用 SparseCE 来表示，只需要存两个整数 [0, 2]，结束了。内存占用从 1000 个元素减少到 2个元素，效率提升 500倍！

## 4. PyTorch 中的使用

PyTorch 没有单独的 “SparseCrossEntropyLoss"，`nn.CrossEntropyLoss` 默认就是稀疏格式，它直接接受整数索引标签（比如 0, 1, 2），而不是 one-hot 向量。因为稀疏格式更高效，PyTorch 直接把它作为默认实现。

| 损失函数               | nn 模块（类）            | F 函数库（函数）                       |
| ---------------------- | ------------------------ | -------------------------------------- |
| 二元交叉熵             | `nn.BCELoss()`           | `F.binary_cross_entropy()`             |
| 二元交叉熵（带logits） | `nn.BCEWithLogitsLoss()` | `F.binary_cross_entropy_with_logits()` |
| 交叉熵（多分类）       | `nn.CrossEntropyLoss()`  | `F.cross_entropy()`                    |

常用的是后两个 API，因为内部自带对应的激活函数（sigmoid/softmax），而 `nn.BCELoss()` 需要手动加 sigmoid。此外：

- **nn 模块** 是一个类，需要先实例化（适合在训练循环外定义）
- **F 函数库（函数）** 是一个函数，直接调用（适合在训练循环内临时使用）

```py
import torch
import torch.nn as nn

# 定义模型和损失函数
model = simpleMLP()
criterion = nn.CrossEntropyLoss()  # 多分类任务，用交叉熵
# criterion = nn.BCEWithLogitsLoss() # 二分类任务

optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

# 训练循环
for epoch in range(100):
    # 1. 前向传播
    prediction = model(x)
    # 2. 计算损失
    loss = criterion(prediction, y)  # y 是整数索引标签
    # loss = criterion(prediction, y)  # y 是整数索引标签

    # 3. 反向传播和优化
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

## 5. 理论基础：信息论

### 5.1 信息量：越意外的信息越有价值

信息量衡量的是 **一个事件发生时带来的"惊讶程度"**：

$$
I(x) = -\log{(p(x))}
$$

- **p(x)** ：事件 x 发生的概率
- **log** ：通常用以 2 为底（单位是比特）或自然对数（单位是纳特）

| 事件             | 概率 $p(x)$ | 信息量 $I(x)$ | 解释               |
| ---------------- | ----------- | ------------- | ------------------ |
| 太阳从东边升起   | ≈1.0        | ≈0            | 太常见，没啥信息量 |
| 抛一次硬币是正面 | 0.5         | 1 比特        | 有一定不确定性     |
| 中彩票头奖       | 0.0000001   | ≈23 比特      | 太罕见，信息量爆炸 |

概率越高，信息量越小（习以为常了）；概率越低，信息量越大（惊喜！）。

### 5.2 香农熵：衡量不确定性的指标

香农熵是**信息量的期望值**，衡量一个概率分布的不确定性：

$$
H(p) = -\sum_{x}p(x)\log{p(x)}
$$

举一个简单例子，箱子里有 100 个球，只有两种颜色，蓝色球和红色球，你闭眼摸一个球，问："摸到的是红球还是蓝球？"

- **50个红球，50个蓝球**：此时，不确定性最大，熵值为 1.0
- **90个红球，10个蓝球**：此时，红球的概率较大，不确定性较小，熵值为 0.47
- **100个红球，0个蓝球**：你知道一定是红球，没有不确定性，熵值为 0

🎯 熵（香农熵） = "你需要多少信息才能确定结果"，**核心规律，记住这个规律就对了**：

| 概率分布                     | 不确定性 | 熵值 |
| ---------------------------- | -------- | ---- |
| 均匀分布（所有结果概率一样） | 最大     | 最大 |
| 偏向分布（某个结果概率更高） | 中等     | 中等 |
| 确定分布（某个结果概率100%） | 最小     | 0    |

### 5.3 交叉熵：用错误的猜测需要付出多少代价？

交叉熵就是：你猜错了，需要多花多少"代价"。你猜得越准，代价越小；你猜得越离谱，代价越大。**关键点**：p 和 q 越接近，交叉熵越小！

$$
H(p, q) = -\sum{p(x)\log{q(x)}}
$$

| 场景 | 真实情况                | 你的猜测            | 交叉熵（代价）         |
| ---- | ----------------------- | ------------------- | ---------------------- |
| 做饭 | 客人口味：辣50% 不辣50% | 你做：辣50% 不辣50% | 0（客人满意）          |
| 做饭 | 客人口味：辣50% 不辣50% | 你做：辣100% 不辣0% | 很大（一半客人不满意） |

💡 为什么叫"交叉熵"？

- **"交叉"** = 你的猜测和真实情况"交叉"在一起
- **"熵"** = 不确定性/混乱程度
- **交叉熵** = 用你的猜测去描述真实情况时的混乱程度

### 5.4 KL散度：概率分布之间的差异

KL散度（Kullback-Leibler Divergence）衡量的是：两个概率分布之间的差异。公式可以写成两种形式：

$$
D_{KL}(p||q)=\sum_{x}p(x)\log{\frac{p(x)}{q(x)}}=H(p,q)-H(p)
$$

翻译成白话文就是：`你的猜测和真实情况差多少`。举一个上学的例子，全班数学模考的考试成绩出来了，真实情况是，及格的人有 80%，不及格的人有 20%。

| 你的猜测 | 及格 | 不及格 | KL散度 | 解释                |
| -------- | ---- | ------ | ------ | ------------------- |
| 完全正确 | 80%  | 20%    | 0      | ✅ 完全猜对         |
| 稍微偏差 | 85%  | 15%    | 0.0093 | ❌ 有差距，但很小   |
| 中等偏差 | 90%  | 10%    | 0.0444 | ❌ 有差距，中等     |
| 较大偏差 | 50%  | 50%    | 0.1927 | ❌❌ 差距较大       |
| 完全相反 | 10%  | 90%    | 1.3627 | ❌❌❌ 差距超级大   |
| 完全错误 | 100% | 0%     | ∞      | ❌❌❌❌ 差距无穷大 |

关于 KL 散度还有几个性质，第一个 **非负性** 很好理解，两者之间的不存在差异为 0，只要存在差异必然大于 0。第二个 **不对称性** 需要说明一下：

$$
D_{KL}(p||q) \not ={D_{KL}(q||p)}
$$

- 场景A：真实是80%及格，你猜成90%及格

$$
D_{KL}(p||q)=0.8\times\log{\frac{0.8}{0.9}}+0.2\times\log{\frac{0.2}{0.1}}=0.045
$$

- 场景B：真实是90%及格，你猜成80%及格

$$
D_{KL}(p||q)=0.9\times\log{\frac{0.9}{0.8}}+0.1\times\log{\frac{0.1}{0.2}}=0.037
$$

### 5.5 为什么交叉熵可以做损失函数？

在机器学习中，我们的目标是：让模型的预测分布 q 尽可能接近真实分布 p。

$$
D_{KL}(p||q)=H(p,q)-H(p)
$$

从 KL 散度的定义出发，在训练过程中：

- p 是 **真实标签分布**（固定不变）
- H(p) 是 **真实分布的熵**（常数）
- H(p,q) 是 **交叉熵**（随模型参数变化）

因此，**最小化交叉熵等价于最小化 KL 散度！**。交叉熵越小，预测分布 q 就越接近真实分布 p。
