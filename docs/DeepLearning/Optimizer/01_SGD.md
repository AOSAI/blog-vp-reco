## 1. 梯度下降与学习率

### 1.1 一个思想实验：蒙眼下山

想象你蒙着眼站在一座山上，任务是走到山脚。你看不见路，但你能感觉到脚下的坡度。你往左探一步，感觉地面在抬升；往右探一步，感觉地面在下降。你该怎么办？你的直觉会告诉你三件事：

1. 先判断哪边是下坡 — 这就是 **梯度**
2. 朝下坡方向走 — 这就是 **下降**
3. 控制每一步迈多大，别滚下去 — 这就是 **学习率**

整个深度学习的优化，归根到底就是这三件事。下面我们逐个拆开来看。

### 1.2 梯度：脚下的坡度

1. 梯度的直觉：**梯度是一个向量，指向函数上升最快的方向。**

站在山上，你伸出脚向各个方向探了探，发现往北走地面抬升最快。这个"往北"的方向，就是梯度方向。你脚底感受到的"倾斜程度"，就是梯度的大小。

![1. 一维函数某点的切线示意 =560x](/DeepLearning/Optimizer/01_GD.png)

2. 从一元到多元：**导数与偏导数的意义**

- **一元函数** $f(x)$：梯度就是导数 $f'(x)$。导数告诉你"往正方向走函数是升还是降，升/降得有多快"。
  - $f'(x) > 0$：正方向是上坡
  - $f'(x) < 0$：正方向是下坡
  - $|f'(x)|$ 越大：坡越陡

- **多元函数** $f(x_1, x_2, ..., x_n)$：梯度就是**偏导数**的向量：

$$
\nabla f = \left[\frac{\partial f}{\partial x_1}, \frac{\partial f}{\partial x_2}, ..., \frac{\partial f}{\partial x_n}\right]
$$

每个分量告诉你：==沿这个坐标轴方向移动时，函数变化得有多快==。

![2. 二维曲面上某点的梯度箭头 =560x](/DeepLearning/Optimizer/02_GD.png)

为什么叫"梯度"？在微积分里，同一个数学对象有三个名字，但角度不同：

| 名称                                         | 视角             | 适合场景           |
| -------------------------------------------- | ---------------- | ------------------ |
| **导数** $f'(x)$                             | 变化率（有多快） | 一元函数           |
| **偏导数** $\frac{\partial f}{\partial x_i}$ | 单个方向的变化率 | 多元函数的分量     |
| **梯度** $\nabla f$                          | 方向 + 大小      | 需要"往哪走"的时候 |

神经网络有成百上千万的参数，我们关心的不是"某一个方向变化多快"，而是"**往哪个方向调参数，损失降得最快**"。这时候，"梯度"这个名字就再合适不过了。在深度学习中：

- 损失函数 $L(w)$ = 我们站的那座"山"
- 模型参数 $w$ = 我们在山上的位置
- 梯度 $\nabla L(w)$ = 当前脚底感知到的坡度

> **一句话记住**：梯度是你的"坡度探测器"，告诉你哪边是上坡、坡有多陡。

### 1.3 下降：逆着梯度走

**核心逻辑**：梯度指向**上坡**方向。但我们的目标是**下坡**（让损失变小）。所以策略很简单：**反着走**。

$$
w_{t+1} = w_t - \eta \nabla L(w_t)
$$

把这个公式拆成三步来理解：

- **$w_t$**：你当前站的位置（当前的参数值）
- **$\nabla L(w_t)$**：梯度，告诉你哪边是上坡
- **$-\eta \nabla L(w_t)$**：逆着上坡方向，跨出 $\eta$ 大小的步子

这就是**梯度下降**（Gradient Descent）的核心思想：==永远朝着梯度反方向迈步==。

你可能会问："既然梯度是'上升'方向，那直接取负号就是'下降'，为什么不干脆定义一个'下降梯度'？"

数学上梯度有严格的定义：它是**方向导数的最大值**，天然指向"上升最快"的方向。我们尊重这个定义，然后在应用的时候取反。就像你开车，油门是"加速"，你想减速时不会把油门改名叫"减速"，而是松油门或踩刹车。

![3. 小球沿梯度反方向滚向谷底 =560x](/DeepLearning/Optimizer/03_GD.png)

| 方向       | 公式                | 结果                |
| ---------- | ------------------- | ------------------- |
| 梯度方向   | $w + \eta \nabla L$ | 损失变大（上山）    |
| 梯度反方向 | $w - \eta \nabla L$ | 损失变小（下山） ✅ |

> **一句话记住**：梯度指上坡，我们走下坡，这就是"梯度下降"。

### 1.4 学习率：一步跨多大

**步长的艺术**：学习率 $\eta$ 控制你每一步迈多大。它是整个训练过程中最重要的超参数之一。

$$
w_{t+1} = w_t - \eta \nabla L(w_t)
$$

三个场景，一步之差：

| 学习率                  | 比喻       | 后果                                     |
| ----------------------- | ---------- | ---------------------------------------- |
| **太小** ($\eta=0.001$) | 老太太挪步 | 走了半天还在原地，可能困在小坑里出不来   |
| **正好** ($\eta=0.1$)   | 正常人走路 | 平稳快速到达谷底                         |
| **太大** ($\eta=1.0$)   | 疯子狂奔   | 一步跨过山谷，在两边来回弹跳甚至飞出山外 |

![4. 三种学习率在同一个函数上的轨迹对比 =560x](/DeepLearning/Optimizer/04_GD.png)

**学习率的本质**不是"速度"，而是**对梯度的信任程度**。

- 梯度告诉你方向，但它只是一个**局部**的估计：你脚下这一小块地面的倾斜方向。
- 如果你完全相信梯度（学习率 = 1），那就大步流星往前走。但万一脚下的地形只是一个小凹陷呢？你可能一步就跨过真正的谷底了。
- 如果你不太相信（学习率 = 0.001），那就小心翼翼挪步。虽然稳妥，但可能要走到猴年马月。

你可能会问："学习率是固定的好，还是变的好？"

固定的简单，但不够灵活。理想的策略是：**一开始大步快跑，快到谷底时放慢脚步，小心试探**。这就是后面要讲的**学习率衰减**和**自适应学习率**（比如 Adam 优化器）在做的事。

> **一句话记住**：学习率是你对梯度的"信任度"，信太多会跑偏，信太少走不动。

### 1.5 一次迭代的全过程

把上面三个概念串起来，看一个具体的数值例子。

假设损失函数 $L(w) = w^2$，当前参数 $w = 3$，学习率 $\eta = 0.1$：

| 步骤             | 计算过程                       | 结果                           |
| ---------------- | ------------------------------ | ------------------------------ |
| **① 当前位置**   | $w_t = 3$                      | 损失 $L(3) = 9$                |
| **② 算梯度**     | $\nabla L(3) = 2 \times 3 = 6$ | 梯度是 6，指向正方向           |
| **③ 算下降方向** | $-6$                           | 往负方向走                     |
| **④ 乘学习率**   | $-0.1 \times 6 = -0.6$         | 往负方向走 0.6 步              |
| **⑤ 更新参数**   | $w_{t+1} = 3 - 0.6 = 2.4$      | 损失 $L(2.4) = 5.76$ ✅ 下降了 |

只走了一步，损失就从 9 降到了 5.76。重复这个过程，参数会越来越接近谷底 $w=0$。

下面用一个极简的代码跑一遍，看看 20 步迭代的完整轨迹：

```python
w = 3.0
eta = 0.1

for i in range(20):
    grad = 2 * w          # 梯度 = 导数
    w = w - eta * grad    # 梯度下降
    loss = w ** 2
    print(f"Step {i:2d}: w = {w:.4f}, loss = {loss:.4f}")
```

输出：

```
Step  0: w = 2.4000, loss = 5.7600
Step  1: w = 1.9200, loss = 3.6864
Step  2: w = 1.5360, loss = 2.3593
Step  3: w = 1.2288, loss = 1.5099
Step  8: w = 0.4031, loss = 0.1625
Step 18: w = 0.0270, loss = 0.0007
```

![5. SGD 在抛物线上的迭代轨迹 =560x](/DeepLearning/Optimizer/05_GD.png)

可以看到，参数 $w$ 从 3.0 一步步走向 0，损失从 9 一步步降到接近 0。这就是梯度下降在做的事。

## 2. 随机梯度下降：SGD

### 2.1 三种梯度下降的直觉对比

上一节说的梯度下降，其实有一个更完整的名字：**批量梯度下降（Batch Gradient Descent, BGD）**。之所以叫"批量"，是因为它每次都用**全部数据**来计算梯度。但还有另外两个变体：

| 类型               | 每次用多少数据  | 设计哲学   | 比喻                         |
| ------------------ | --------------- | ---------- | ---------------------------- |
| **BGD（批量）**    | 整个训练集      | 三思而后行 | 等所有数据都看完了再做决定   |
| **SGD（随机）**    | 1 个样本        | 直觉决策   | 看到一个数据就行动，错了再改 |
| **Mini-batch SGD** | 一小批（如 32） | 小组讨论   | 听一小群人的意见做决定       |

三者的命运截然不同：

- **BGD**：理论上最准，梯度方向最稳定。但现实中没人用 --> 今天的训练集动辄几百 GB，不可能一次性装进内存。
- **SGD**：只用一个样本算梯度，方向噪声极大。但有意思的是，这股"不确定性"反而成了它的优势 --> 噪声能帮它跳出局部陷阱。
- **Mini-batch SGD**：取一个折中。计算量适中 + 梯度方向相对稳定。**这就是 PyTorch 中 `optim.SGD` 实际在做的事**。

![6. BGD / SGD / Mini-batch 三种路径对比 =560x](/DeepLearning/Optimizer/06_SGD.png)

你可能会问："既然 SGD 噪声大，为什么它反而可能比 BGD 效果好？"

因为 BGD 过于"执着"——它看到的梯度是整个数据集的平均方向，如果初始点在一个小凹陷旁边，它会义无反顾地滑进去。而 SGD 每一步都带着随机扰动，有时候恰巧能"颠"出这个凹陷，走向更优的解。

### 2.2 公式的变化：从全量到随机

三种方式的公式放在一起对比，区别一目了然（唯一的区别是 **对多少个样本的梯度做平均**）：

| 类型           | 公式                                                                       | 含义                              |
| -------------- | -------------------------------------------------------------------------- | --------------------------------- |
| **BGD**        | $\theta = \theta - \eta \cdot \frac{1}{N}\sum_{i=1}^{N}\nabla L_i(\theta)$ | 等于 N 个样本的平均（最稳，最慢） |
| **SGD**        | $\theta = \theta - \eta \cdot \nabla L_i(\theta)$                          | 等于 1 个样本的梯度（最抖，最快） |
| **Mini-batch** | $\theta = \theta - \eta \cdot \frac{1}{B}\sum_{i=1}^{B}\nabla L_i(\theta)$ | 等于 B 个样本的平均（又稳又快）   |

> **一句话记住**：三个算法本质上是同一个公式，只是 `batch_size` 从 `N` 变 `1` 变 `B` 的区别。

### 2.3 残酷的现实：只有一种梯度下降

理论上讲有三种，实际上只有一种。现代深度学习训练集的规模是：Llama 3 训练了 15 万亿 token，GPT-4 不知道，但只多不少。==没有任何 GPU 能把这么多数据一次性装进显存==。所以 BGD 早已名存实亡。

严格来说，现在代码里写的 `optim.SGD`，**全部都是 Mini-batch SGD**。那为什么还叫 SGD？

历史原因。早期深度学习的数据集还很小（比如 MNIST 只有 6 万张图，并且每张图分辨率很低，内存占用较小），那个时候真的有"一个样本更新一次"的用法。

后来数据量暴涨，大家自然过渡到了 Mini-batch，但"随机梯度下降"这个名字留了下来。**所以，batch_size 不是一个算法的选择，而是一个超参数：**

- ==batch_size = 1== --> 行为像 SGD（高噪声）
- ==batch_size = len(dataset)== --> 行为像 BGD（但基本跑不动）
- ==batch_size = 32 / 64 / 128== --> 最常用的区间（平衡稳定性和效率）

实际选 batch_size 时，考虑的不是"用哪种梯度下降"，而是：**显存能塞下多大 batch 就设多大**。

### 2.4 PyTorch 中的用法

用法极其简单，三个步骤：

```python
import torch
import torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset

# 1. 定义模型
model = nn.Linear(10, 1)

# 2. 定义优化器（SGD = Mini-batch SGD）
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)

# 3. 训练循环（DataLoader 自动切 batch）
dataset = TensorDataset(X, y)
dataloader = DataLoader(dataset, batch_size=32, shuffle=True)

for epoch in range(100):
    for batch_x, batch_y in dataloader:      # ← 每次取 32 个样本
        pred = model(batch_x)                 # 前向传播
        loss = loss_fn(pred, batch_y)          # 算损失（当前 batch 的）

        optimizer.zero_grad()                 # 清零梯度
        loss.backward()                       # 算梯度（当前 batch 的平均梯度）
        optimizer.step()                      # 用平均梯度更新参数
```

注意看这四行 ——`zero_grad` → `backward` → `step` —— 这是 PyTorch 的标准模式。无论你用什么优化器，这个循环都不会变。

![8. Epoch / Batch / Iteration 关系示意 =560x](/DeepLearning/Optimizer/08_SGD.png)

关键概念：

- **epoch**：完整遍历了一遍训练集
- **batch**：一次迭代用的数据子集（大小 = batch_size）
- **iteration**：一次参数更新（一个 batch 前传 → 反传 → 更新）

$$
\text{每个 epoch 的 iteration 数} = \frac{\text{总样本数}}{\text{batch\_size}}
$$

### 2.5 重要的超参数

`torch.optim.SGD` 最常用的参数：

| 参数           | 含义                   | 默认值 | 说明                                      |
| -------------- | ---------------------- | ------ | ----------------------------------------- |
| `params`       | 要优化的参数           | 必填   | 通常是 `model.parameters()`               |
| `lr`           | 学习率 $lr$            | 必填   | 最重要的超参数，见第 1.4 节               |
| `momentum`     | 动量系数 $\beta$       | 0      | 相当于惯性，取值范围为 [0, 1)             |
| `weight_decay` | 权重衰减系数 $\lambda$ | 0      | 等价于 L2 正则化，取值一般为 [1e-5, 1e-2] |
| `nesterov`     | Nesterov 动量          | False  | momentum 的改进版                         |

## 3. 超参数的补充说明

### 3.1 一个迟到 50 年的发明：momentum

1964 年，苏联数学家 Polyak 写了一篇论文。论文里他提出了一个想法：**给梯度下降加上一个"惯性项"，让更新方向不仅看当前的梯度，还保留一部分上一回的方向**。这个想法在数学上很完美，然后 … … 就没有然后了。因为当时根本没有任何需要它的场景。

#### 3.1.1 推铁球下山

Momentum 的直觉非常朴素：**给优化装一个惯性轮**。

想象你在推一个很重的铁球下山。你不是每走一步就重新发力，而是让球带着之前的冲劲继续滚。就算突然遇到一段平路或者一个小上坡，球也能靠惯性冲过去。

动量做的就是这件事：每次更新时，保留之前的方向记忆，下一次先按记忆走大半，再看当前梯度微调。

![9. SGD 与 SGD+Momentum 在窄山谷中的路径对比 =560x](/DeepLearning/Optimizer/09_SGD_opt.png)

这个图很有意思，我们看到梯度第一次是朝右下方下降的，90% 的动量惯性太大了，走多了，包括后续到终点的时候，惯性太大，滑过了，最后才滑回来。

#### 3.1.2 公式解析

```
v = β·v  + η·∇L      ← 累积历史梯度（带衰减）
w = w - v            ← 用累积方向更新
```

1. **当前梯度** $\eta \nabla L$：你脚下感知到的坡度
2. **历史累积** $\beta v$：之前几步的冲劲，$\beta$ 通常取 0.9，意思就是 90% 靠惯性、10% 看当下
3. **合起来** $v$：这一次实际迈出的方向

#### 3.1.3 为什么 momentum 能解决 zigzag（之字形震荡）？

这是整篇博客最值得记住的一张图。

```
      等高线
      ╱‾‾‾╲
  ──╱  ───  ╲──   ← SGD 的路径：左右来回撞墙
   ╱  ↓  ↑   ╲
  ╱___________╲
    → 缓慢前进
```

想象一个横长竖窄的山谷，比如我们下山，到了山中腰时，要左拐下山，因为当前下山的路两边都有小山坡，如果是向下滚动的小球，就会来回的在小山谷之间来回的之字形滑动着下降。

以上只是理想的描述，实际上这些小山谷都是悬崖峭壁，甚至下山的路都是平的。产生这种问题的原因有很多，比如：

- **不同层的梯度差万倍**：CNN 底层梯度往往是顶层梯度的 1/100~1/10000 → 损失面就是横长竖窄的山谷
- **特征数值范围不同**：年龄（200以内） vs 收入（很多个0） → 同样的
- **embedding 层 vs 全连接层**：参数量差几个数量级 → 同样的

梯度在山谷左右壁上来回震荡：如果**没有 momentum**，每步都在左右横跳，几乎没有前进；

**有 momentum** 的情况下，左右震荡的方向上，这一步向左、下一步向右，积累了互相抵消。沿山谷的方向上，每一步都向前，积累起来越走越快。所以 momentum 被归类为 **"加速方法"**，它在平坦方向上真的在加速。

#### 3.1.4 黄金期只有 3 年

它的故事很有意思：

- ==2012 年之前==：网络浅、数据少，Plain SGD 就够用了，没人需要 momentum
- ==2012 到 2014 年==：AlexNet、VGG、ResNet 把网络从 3 层推到了 50–150 层，Plain SGD 在山谷中剧烈震荡，根本训不动
- ==2014 到 2016 年==：**SGD + Momentum 0.9** 成为标准配置，几乎所有经典论文都在用
- ==2015 年==：**Adam 发布**，不仅带了 momentum，还带了自适应学习率，一个 API 全部搞定

`Plain SGD = 最朴素的梯度下降，不加任何额外操作。没有 momentum、没有自适应学习率、没有权重衰减、没有学习率调度。就是"沿着梯度反方向迈一小步"。`

所以不是 momentum 没被广泛使用过。它刚成为标配两三年，Adam 就接管了战场。它的存在感恰好被夹在 Plain SGD 和 Adam 之间，给人一种"昙花一现"的错觉。

所以现在没有系统整理过发展历史的同学可能会发出灵魂拷问："SGD 还支持 momentum？那不是 Adam 才有的吗？"

Momentum 最开始就是给 SGD 设计的。Adam 的"自适应学习率"是完全不同的改进方向，它不只有 momentum（一阶动量），还引入了梯度的二阶动量来动态调整每一步的学习率。我们放到下一篇再讲。

### 3.2 权重衰减：weight_decay

#### 3.2.1 直觉与公式

权重衰减这个词已经把自己说明白了：**每次更新参数之前，先把参数缩小一丁点**。类似于你的银行账户每个月被扣 0.1% 的管理费，工资到账前已经缩了一点水。

SGD 标准更新：

$$
w = w - \eta \nabla L
$$

加上 weight_decay 系数 $\lambda$ 后：

$$
w = w - \eta (\nabla L + \lambda w) = \eta\nabla{L} + (1-\eta\lambda)w
$$

把括号拆开，就变成了两个步骤：

1. **先衰减**：$(1 - \eta \lambda)w$ --> 每个权重都缩水一点
2. **再下降**：减去梯度方向走一步

你可能会问："这一步缩水是为什么？"，是为了让模型无法 "死记硬背" 那些不重要的特征：

- 如果一个权重一直在更新（说明它确实有用），每次衰减后立刻又被梯度拉了回来，基本不受影响
- 如果一个权重几乎不被梯度更新（说明它不重要），它会越缩越小，直到几乎归零

#### 3.2.2 常用值

| 模型规模             | 推荐 $\lambda$                           | 原因                       |
| -------------------- | ---------------------------------------- | -------------------------- |
| 小模型（几百万参数） | $1 \times 10^{-4}$                       | 防止过拟合                 |
| 大模型（LLM）        | $5 \times 10^{-5}$ 或 $1 \times 10^{-5}$ | 参数足够多，不需要太强正则 |

---

### 3.3 L1 与 L2：两种"罚款"风格

#### 3.3.1 同一个目标，不同的方法

L1 和 L2 正则化做的事情一模一样：**不让参数的绝对值太大**。但它们罚款的方式完全不同：

| 类型 | 罚多少            | 对小参数的态度                       |
| ---- | ----------------- | ------------------------------------ |
| L2   | $\lambda \|w\|^2$ | 几乎不管（$0.1^2 = 0.01$，微不足道） |
| L1   | $\lambda \|w\|$   | 一视同仁（$0.1 = 0.1$，照样罚）      |

- **L2**：按参数大小的平方罚款。$w=5$ 罚 25，$w=0.1$ 罚 0.01。==对小参数睁一只眼闭一只眼，把压力集中在大参数上==
- **L1**：按参数大小直接罚款。$w=5$ 罚 5，$w=0.1$ 罚 0.1。==连小参数也会被罚到归零==

#### 3.3.2 为什么 L1 能产生稀疏解（参数变 0）？

![10. L1（菱形）与 L2（圆形）的等高线对比 =560x](/DeepLearning/Optimizer/10_SGD_opt.png)

用几何直觉来理解。L1 的约束区域是一个**菱形**，顶点在坐标轴上；L2 的约束区域是一个**圆形**，没有顶点。当你把椭圆形的损失函数等高线套上去时：

- 菱形在顶点处有"尖角"——最优解很容易落在某个坐标轴上的那个尖角，对应的另一个维度自然就是 0
- 圆形没有这样的尖角——最优解大概率不在坐标轴上，参数不会归零

这个差别的意义：**L1 会自动为你做特征选择**。如果 100 个输入特征里只有 10 个有用，L1 会把另外 90 个的参数直接推到 0，相当于自动丢弃了它们。L2 不会，它只会让那些参数变得很小，但不会完全归零。

#### 3.3.3 怎么选

| 场景               | 推荐                          | 原因               |
| ------------------ | ----------------------------- | ------------------ |
| 正常训练防过拟合   | **L2**（直接设 weight_decay） | 平滑稳定，框架自带 |
| 特征太多想自动筛选 | **L1**（手写加入 loss）       | 让无关特征自动归零 |
| 两者都要           | ElasticNet（L1 + L2）         | 各取一半           |

PyTorch 内置的 `weight_decay` 就是 L2。如果你要用 L1，得手动加一行：

```python
loss = loss_fn(pred, y) + lamda * torch.norm(model.weight, 1)
```

### 3.4 先伸脚探路再走：Nesterov 动量

#### 3.4.1 极小改动，极大惊喜

Nesterov 看起来只是 momentum 的一个微小改动，但效果好得出奇。

再回顾一下普通 momentum：站在 A 点 → 算 A 点的梯度 → 带着惯性走到 B。

Nesterov 改了一个顺序：站在 A 点 → **先按惯性走到 A'** → 算 A' 的梯度 → 从 A 点出发，用 A' 的梯度修正方向 → 走到 B。

#### 3.4.2 生活中的类比

- **Momentum**：闭着眼睛往前走，走完了再睁眼看走到了哪，下步再补方向
- **Nesterov**：先眯一只眼往前探一步，看清前面的地形，再决定这一步往哪踩

开车过弯是更好的例子：

- Momentum 是到了弯心才发现要打方向盘，急转
- Nesterov 是入弯前就已经打了方向，平顺通过

![11. Momentum 与 Nesterov 的走法对比 =560x](/DeepLearning/Optimizer/11_SGD_opt.png)

#### 3.4.3 在 PyTorch 中使用

先来看一个 Nesterov 的伪代码，与 Momentum 的区别只有一行，但效果确实更好。收敛更快，震荡更小。

```python
# Momentum
v = beta * v + eta * grad(w)
w = w - v

# Nesterov
w_lookahead = w - beta * v       # 先预看一步
v = beta * v + eta * grad(w_lookahead)  # 算预看位置的梯度
w = w - v                        # 从原位置更新
```

实际的 PyTorch 使用当中，加一个 `nesterov=True` 就行：

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.01,
    momentum=0.9,
    nesterov=True,
)
```

注意：momentum 必须开启（不为 0）时才能用 Nesterov，因为它是 momentum 的改进，不是独立存在的东西。
