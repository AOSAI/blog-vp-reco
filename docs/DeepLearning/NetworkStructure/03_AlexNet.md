## 1. 23 年的空白：从 LeNet 到 AlexNet

### 1.1 LeNet 走到的尽头

上一篇文章里，LeNet-5 展示了 CNN 的基本骨架：“卷积 + 池化 + 全连接”。它在 MNIST 手写数字上取得了 0.8% 的错误率，证明了"局部连接 + 权值共享"这个思路确实有效。

但 LeNet 在 MNIST 上的成功，也暴露了一个深层问题：**LeNet 的结构是为 28×28 的灰度小图量身定做的**。5 层卷积（严格说是 3 层卷积 + 2 层池化）、~62K 参数，刚好够用——也刚好不够扩展到更大的数据。

当时的共识是：CNN 能做手写数字识别，但仅限于此。

### 1.2 三座大山

从 1989 到 2012，CNN 的规模一直被三件事卡住。

**数据**：LeNet 时代最大的公开数据集 MNIST 只有 6 万张图，10 个类。1000 类、百万级的图像数据集在 2009 年之前根本不存在。没有数据，大网络训了也白训。

**硬件**：1998 年的 GPU（NVIDIA RIVA 128）只有 4MB 显存。LeNet 在 CPU 上跑只需要几毫秒，但一个 10 倍深的网络需要的不只是时间——它需要显存能装下中间特征图。一张 227×227 的 RGB 图经过 5 层卷积后的特征图就有几十 MB，1998 年的显卡根本放不下。

**梯度**：tanh 和 sigmoid 在深层网络里面临严重的饱和问题。层数一深，梯度在反向传播时指数级衰减（梯度消失），浅层几乎学不动。LeNet 只有 5 层，勉强能用；但如果想堆到 8 层、10 层、20 层，tanh 就是第一道墙。

2006 年 Hinton 的深度信念网络（DBN）证明了"深度"的价值，但 CNN 的扩展仍然被数据和硬件拖着。直到 2009 年 ImageNet 诞生，2010 年 GPU 的显存和计算力大幅提升，这两座大山才被搬开。

剩下那一座大山：**“梯度饱和”**，就是 AlexNet 的结构创新要解决的问题。

### 1.3 2012：一切到位

2012 年，Alex Krizhevsky 带着他的 AlexNet 参加了 ImageNet 大规模视觉识别挑战赛（ILSVRC-2012），以 top-5 错误率 15.3%（第二名 26.2%）的压倒性优势夺冠。**top-5** 的意思是：模型输出概率最高的 5 个类别中只要包含正确类别就算对。更严格的 **top-1**（只有概率最高的一个类别是正确才算对）也同样大幅领先。

AlexNet 不是第一个 CNN，也不是第一个深度网络。它是第一个把 ==数据（ImageNet）+ 硬件（GTX 580 双卡）+ 结构（ReLU + Dropout + 5 层卷积）== 这三件事同时做到位的网络。

> AlexNet 的成功不是某一个创新，而是"更大的模型 + 更大的数据 + 更好的硬件"三件事在同一年汇合。

## 2. AlexNet 的结构拆解

AlexNet 在结构上有几个关键改进。每个改进单独看都不复杂，但组合在一起，让 5 层卷积 + 3 层全连接、62M 参数的庞然大物第一次真正"能训"。

### 2.1 ReLU：更深而不饱和

LeNet 用 tanh，AlexNet 换成 [ReLU](../ActivationFunction/02_ReLU.md)：这是结构层面最关键的改变。

$$
\text{ReLU}(x) = \max(0, x)
$$

ReLU 在正半区导数为 1，梯度在反向传播时不会衰减。用 tanh 堆 8 层，浅层的梯度已经小到几乎不更新了；用 ReLU 堆 8 层，每一层的梯度都维持在同样量级。

> **设计哲学**：ReLU 不是比 tanh "更精确"，而是让深层的梯度能"流下去"。

### 2.2 Dropout：在哪里正则化

AlexNet 有 62M 参数，其中三个全连接层占了 58.6M（~94%）。FC6（第一个全连接层，Fully Connected）一个层就有 37.7M 参数，比 LeNet 整个网络的 62K 多了 600 倍。

全连接层多到这种程度，过拟合是必然的。AlexNet 的结构解法是 **Dropout**（一种正则化技术）：在前向传播时，以概率 $p=0.5$ 随机丢弃 FC6 和 FC7 的神经元（不更新也不参与反向传播）。

![Fig.1 Dropout：每次前向传播随机"关掉"一半神经元 =560x](/DeepLearning/Network/03_alexnet_01.png)

> **设计哲学**：Dropout 放在全连接层，而不是卷积层。因为卷积层本身就是"权值共享"的——参数已经在空间上被分摊了，天然有正则化效果。全连接层参数高度集中，才是正则化的主战场。

Dropout 只在训练时生效，推理时要关闭（所有神经元都激活，权重乘 $1-p$ 做补偿）。

### 2.3 局部响应归一化（LRN）

==ReLU 没有上界，输入很大时输出也很大（y=x），不像 tanh/sigmoid 那样会自动饱和==。

这带来一个问题：**通道之间的激活值可能差异极大**。某个通道学到的特征响应特别强，另一个通道学到的东西虽然有用但值偏小，就会被大的通道"淹没"，白训了。

AlexNet 在 Conv1 和 Conv2 之后加了一层 **局部响应归一化（Local Response Normalization, LRN）**，对相邻通道的响应做"==侧向抑制=="。

$$
b_{x,y}^{i} = a_{x,y}^{i} / \left(k + \alpha \sum_{j=\max(0,i-n/2)}^{\min(N-1,i+n/2)}(a_{x,y}^{j})^2\right)^{\beta}
$$

**直观理解**：一个通道在位置 $(x,y)$ 的激活值，如果它周围几个通道的激活值也很大，就把它压一压。就像神经元之间的"侧向抑制" —— 大家都在兴奋，你就别太突出；只有你一个兴奋，那就放大。

LRN 在 AlexNet 时代是有效的，但后来被 Batch Normalization 完全取代。LRN 为什么被淘汰？请见 “知识扩展” 部分。

### 2.4 重叠池化

LeNet 的池化层是 $2\times2$ 步长 2，窗口完全不重叠。AlexNet 的池化层用 $3\times3$ 步长 2，窗口之间重叠 1 个像素。

这看似是一个微小的变化，但重叠池化让池化窗口之间的信息有了连续性。AlexNet 在论文中报告，重叠池化把 top-1 错误率降低了约 0.5%。

## 3. 信息流动：227×227 的真实结构

### 3.1 论文中的真实配置

AlexNet 的数据流从一张 227×227×3 的 RGB 图像开始。等一下，论文里写的是 224×224，但按 stride 4 的 11×11 卷积计算：$(224 - 11)/4 + 1 = 54.25$，不是整数。换成 227 就对了：$(227 - 11)/4 + 1 = 55$。

完整的 AlexNet 结构（单 GPU 等效，合并双卡通道）如下：

```
输入 227×227×3 (RGB)
→ Conv1: 96, 11×11, stride 4 → ReLU   → 55×55×96
→ LRN + MaxPool 3×3, stride 2         → 27×27×96
→ Conv2: 256, 5×5, pad 2 → ReLU       → 27×27×256
→ LRN + MaxPool 3×3, stride 2         → 13×13×256
→ Conv3: 384, 3×3, pad 1 → ReLU       → 13×13×384
→ Conv4: 384, 3×3, pad 1 → ReLU       → 13×13×384
→ Conv5: 256, 3×3, pad 1 → ReLU       → 13×13×256
→ MaxPool 3×3, stride 2               → 6×6×256
→ FC6: 9216 → 4096 (Dropout p=0.5)
→ FC7: 4096 → 4096 (Dropout p=0.5)
→ FC8: 4096 → 1000
```

![Fig.2 AlexNet 完整结构：5 层卷积 + 3 层全连接 =660x](/DeepLearning/Network/03_alexnet_02.png)

注意结构中的几个设计点：

- **LRN** 放在 Conv1 和 Conv2 之后、池化之前
- **Dropout**（p=0.5）只出现在 FC6 和 FC7 之后，卷积层不做 Dropout
- 五个卷积层的参数量分布不均：Conv1 仅 3.5 万参数，Conv2~Conv5 每层约 60~130 万，但三个全连接层占了全网络 **62.3M 参数中的 ~94%**（FC6 一个层就有 3775 万）。参数大头全在全连接

一个直观的对比：LeNet 是 62K 参数，AlexNet 是 62.3M——**整整大了 1000 倍**。这 1000 倍不是简单地把层数加一倍，而是每一层的宽度（通道数）和深度（层数）同时扩展的结果。

### 3.3 代码视角

PyTorch 里定义一个 AlexNet，按照论文的 96/256/384/384/256 配置：

```python
import torch.nn as nn

model = nn.Sequential(
    # 5 层卷积
    nn.Conv2d(3, 96, 11, stride=4),      # Conv1
    nn.ReLU(inplace=True),
    nn.LocalResponseNorm(5),              # LRN
    nn.MaxPool2d(3, stride=2),            # Pool1

    nn.Conv2d(96, 256, 5, padding=2),     # Conv2
    nn.ReLU(inplace=True),
    nn.LocalResponseNorm(5),              # LRN
    nn.MaxPool2d(3, stride=2),            # Pool2

    nn.Conv2d(256, 384, 3, padding=1),    # Conv3
    nn.ReLU(inplace=True),

    nn.Conv2d(384, 384, 3, padding=1),    # Conv4
    nn.ReLU(inplace=True),

    nn.Conv2d(384, 256, 3, padding=1),    # Conv5
    nn.ReLU(inplace=True),
    nn.MaxPool2d(3, stride=2),            # Pool3

    nn.Flatten(),

    # 3 层全连接
    nn.Linear(9216, 4096),                # FC6
    nn.ReLU(inplace=True),
    nn.Dropout(0.5),                      # Dropout

    nn.Linear(4096, 4096),                # FC7
    nn.ReLU(inplace=True),
    nn.Dropout(0.5),                      # Dropout

    nn.Linear(4096, 1000),                # FC8
)
```

注意一个实现细节：**inplace=True** 让 ReLU 直接覆盖输入，不需要额外分配内存。AlexNet 在 2012 年用双卡 3GB 显存跑 62M 参数，每一 MB 显存都很珍贵。

## 4. 知识扩展

### 4.1 224 vs 227：论文写 224，代码用 227

AlexNet 论文里写输入是 224×224，但实际代码（Caffe 的 deploy.prototxt）用的是 227×227。Conv1 的 stride 是 4、kernel 是 11，只有 227 才能算出精确的 55×55 输出：$(227 - 11)/4 + 1 = 55$。如果用 224，结果是 54.25（不是整数），Conv1 输出会变成 54×54，这与论文声称的 55×55 不符。

所以 **AlexNet 的实际输入是 227×227**，代码里写的也是 227。

### 4.2 LRN 为什么被淘汰

LRN 的设计直觉是好的：让相邻通道之间"互相抑制"，类似于神经科学里的侧向抑制。但在实践中，LRN 有两个问题：

1. **效果有限**：LRN 只降低了约 1% 的错误率。它有用，但不是关键贡献
2. **被 Batch Normalization 全面替代**：BN 不仅能归一化（解决 LRN 想解决的问题），还能加速收敛、允许更大学习率、提供一定正则化（一石三鸟）

2015 年 BN 出现后，LRN 几乎立即从所有网络结构中消失。现在看 AlexNet 的 LRN，就像一个历史的注脚——在当时有用，但很快被更好的方案取代。

### 4.3 双 GPU：时代的烙印

2012 年的 GTX 580 只有 1.5GB 显存，一张卡装不下 62M 参数的 AlexNet。Krizhevsky 的做法是把网络**切成两半**，分别放在两张显卡上。分割策略很有讲究：

| 层        | GPU 0                               | GPU 1                               | 是否跨 GPU 通信 |
| --------- | ----------------------------------- | ----------------------------------- | --------------- |
| Conv1     | 48 个 11×11 卷积核                  | 48 个 11×11 卷积核                  | 否              |
| Conv2     | 128 个 5×5（只连 GPU 0）            | 128 个 5×5（只连 GPU 1）            | 否              |
| **Conv3** | 192 个 3×3（连**两个 GPU 的输出**） | 192 个 3×3（连**两个 GPU 的输出**） | **是**          |
| Conv4     | 192 个 3×3（只连 GPU 0）            | 192 个 3×3（只连 GPU 1）            | 否              |
| Conv5     | 128 个 3×3（只连 GPU 0）            | 128 个 3×3（只连 GPU 1）            | 否              |
| FC6       | 2048 神经元（连 GPU 0 的 6×6×128）  | 2048 神经元（连 GPU 1 的 6×6×128）  | FC7 时合并      |
| FC7       | 4096（合并两个 GPU）                | —                                   | —               |

![Fig.3 AlexNet 双 GPU 结构：Conv3 是唯一的跨 GPU 层 =600x](/DeepLearning/Network/03_alexnet_03.png)

只有 Conv3 是**跨 GPU** 的——它的每个卷积核都同时看两个 GPU 的特征图，相当于做了一次"信息交换"。这个设计的巧妙之处在于：全连接层合并信息之前，先让卷积层的中间层做一次跨 GPU 通信，避免全连接层的参数量因为合并而翻倍。

今天（单卡显存已到 80GB）这个设计已经不需要了。但在当时，没有这种分割策略，AlexNet 就跑不起来。
